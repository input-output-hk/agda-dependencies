agda-deps

An Agda compiler backend that maps your proof's dependency graph.

A backend for the Agda compiler. It runs inside the type-checker and emits a graph of how every definition, postulate, and unfinished lemma depends on the others — as Graphviz DOT, an interactive HTML view, or stable JSON for downstream tooling.

node states

Four states, one colour each

Every node in the graph is one of four states. The whole tool is built around making the unfinished ones (holes, postulates, failed modules) easy to find and reason about.

D
Defined

Function, datatype, record — elaborated normally.

P
Postulate

An axiom / postulate. A type-level promise, no body.

H
Hole

Contains an unsolved meta (a ? in source).

F
Failed

Module whose type-check failed under --keep-going.

Three output formats

Graphviz

DOT

A .dot graph you can pipe into Graphviz (dot -Tsvg) or any DOT-aware tool. The default format.

Interactive

HTML

A self-contained page in one of 14 views — from module DAGs to source-linked reading order. --lazy splits files for very large corpora.

v2 graph.json

JSON

A stable artifact for downstream tooling: packed (base64 CSR) or expanded (arrays of records) — a versioned wire contract consumers can pin to.

Modes & flags worth knowing

--keep-goingSurvive type-check errors; the failing module is tagged F.
--skip-agdaModule-level graph straight from a source scan — no elaboration, milliseconds at any scale.
--with-sourceAttach the source snippet to every definition; powers the reading / IDE views.
--lazySplit HTML across files so 100k-node projects stay responsive (needs an HTTP server).
--no-externalsDrop everything outside the project root — stdlib and all — from the graph.
--resolve-depsPin Agda's search path to the .agda-lib depend: closure.
--with-term-hashesEmit a canonicalised Word64 fingerprint per definition subterm into the JSON.
--theme / --configColour presets and a kebab-case YAML mirror of every CLI flag.
