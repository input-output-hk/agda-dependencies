agda-deps

An Agda compiler backend

It runs inside the type-checker and emits your proof's dependency graph — one node per definition, each coloured by state: defined, postulated, a hole, or a module that failed to check.

Getting a graph

# install once
cabal install exe:agda-deps --overwrite-policy=always
# emit an interactive HTML view
agda-deps --format=html --view=module-dag-pods \
          --with-source -i test/ -o out/ test/Test.agda

With no --format, the output is Graphviz DOT; a .html or .json path after -o infers the format.

The four states

DDefined
Function, datatype, record — elaborated normally.
PPostulate
An axiom / postulate. A type-level promise, no body.
HHole
Contains an unsolved meta (a ? in source).
FFailed
Module whose type-check failed under --keep-going.

Three outputs

DOT
A .dot graph you can pipe into Graphviz (dot -Tsvg) or any DOT-aware tool. The default format.
HTML
A self-contained page in one of 14 views — from module DAGs to source-linked reading order. --lazy splits files for very large corpora.
JSON
A stable artifact for downstream tooling: packed (base64 CSR) or expanded (arrays of records) — a versioned wire contract consumers can pin to.

Flags worth knowing

--keep-going
Survive type-check errors; the failing module is tagged F.
--skip-agda
Module-level graph straight from a source scan — no elaboration, milliseconds at any scale.
--with-source
Attach the source snippet to every definition; powers the reading / IDE views.
--lazy
Split HTML across files so 100k-node projects stay responsive (needs an HTTP server).
--no-externals
Drop everything outside the project root — stdlib and all — from the graph.
--resolve-deps
Pin Agda's search path to the .agda-lib depend: closure.
--with-term-hashes
Emit a canonicalised Word64 fingerprint per definition subterm into the JSON.
--theme / --config
Colour presets and a kebab-case YAML mirror of every CLI flag.
